# OpenGuardrails, RTX 4090: C4 против U1+U4

Прогон 14 ноября 2026 на Desktop: RTX 4090, драйвер 580.173.02, AMD Ryzen 9 9900X (24 потока), 60 GB RAM,
torch 2.11.0+cu130. Измеритель У1 v4 — коммит `100ce48`, batch 1, бакеты B1–B4.
Модель: `kekwak/OpenGuardrails-Text-4B-0124-mirror` (`3b63e17`), шаблон OpenGuardrails-Text-2510.

Данные: индекс Open собран `prepare-data` по `configs/v4/reindex.json` с нашим оверлеем
`role-corpus-open-task-v2` (manifest `a17cdc95…`, а не закреплённый `da255a70…` У1), итоговый manifest `1736dd5f…`.
Для сравнения вариантов между собой этого достаточно; с цифрами У1 по Open напрямую не сравнивать.

Один baseline и два независимых варианта в режиме `search` по нему (без A/A и парных интервалов):
- `1-c4` — C4: первый токен одним forward, `generate` только если ответ не `safe`;
- `1-u1+u4` — U1+U4 без C4: штатный `generate` HF со статическим кэшем и `torch.compile(mode="reduce-overhead")`.

Вердикты: 0/400 изменений во всех бакетах обоих вариантов.

- C4 убирает шаг декодирования у безопасных ответов (p50 −14 мс), но p95 задают небезопасные ответы с категорией до 10 токенов, их C4 не трогает.
- U1+U4 через штатный `generate` медленнее baseline: статический кэш считает attention по всей выделенной длине, prefill остаётся eager, накладные `generate` не окупаются на 1–10 токенах.
- Для Open берём C4; следующий кандидат — C4 + CUDA graph/compile на prefill (не реализован).
