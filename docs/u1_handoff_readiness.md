# Готовность измерителя

## Laya на RTX 4090: smoke подтверждён, 8 ноября 2026

Текущий скрипт дал `smoke_passed` на Runpod RTX 4090, GPU 0: FP32-веса,
нативный BF16 autocast, `precision_status=recorded_consistent`. Неизменённый
97-wheel lock развёрнут заново; install report совпал по всем wheel SHA256.
Python 3.13.15, torch 2.11.0+cu130, CUDA 13.0, cuDNN 91900, драйвер 595.91.07.

Проверены два входа B1 полной длины 36/512, A→B→A, принятие 512 и отказ 513
до forward, реальные efficient SDPA CUDA kernels и сбор памяти процесса.
Это smoke, не полный baseline или screening. Для inference получен один memory-sample,
поэтому его peak не является надёжным benchmark памяти. Качество не оценивалось.
Семь других моделей и RTX 5090 этим результатом не подтверждаются.

Исходники совпали с отправленным snapshot и локальным кодом; ZIP CRC/SHA256 проверены,
отчёт пересобран offline и полностью совпал. Успешная установка и smoke заняли
103.9 с, сам модельный worker — 8.0 с. Первая bootstrap-попытка остановилась на
PEP 668 до установки lock; сохранена отдельно. Исправлен только launcher: отдельный
driver-venv вместо изменения uv-managed Python. Измерительная логика не менялась.
Pod удалён после скачивания результатов, удаление подтверждено 404; push не выполнялся.
[Validation](../results/u1_handoff/2026-11-08-laya-rtx4090/validation.json),
[manifest исходников worker](../results/u1_handoff/2026-11-08-laya-rtx4090/source_manifest.json).

## Нативный precision Laya, 7 ноября 2026

Установлена причина сообщения `Laya native FP16 autocast changed`: SDK 0.3.20 на
T4 выбирает FP16 по capability <8, а на 4090 использует BF16 из закреплённого
[checkpoint config](https://huggingface.co/convaiinnovations/laya/blob/7b928d828b7b0e022f929d9bd2e44165aa270148/rl_agent_config.json).
Адаптер сохраняет выбор SDK при неизменных FP32-весах и config, без собственной
таблицы GPU/dtype. Принудительный FP16 удалён; CPU fallback/disabled AMP не допускаются.
`metadata.precision` фиксирует режим. Проверки запросов, workers одного варианта
и инженерной baseline/candidate-пары запрещают скрытый дрейф precision.
Параметрические и квантованные различия видны отдельно, действующие критерии не менялись.

CPU-регрессии покрывают исходный выбор SDK FP16/BF16, неизменность config/весов,
отказ при fallback/disabled AMP/неожиданном dtype и последующий дрейф.
Дополнительные регрессии покрывают внешний адаптер без паспорта, memory/quality,
согласованность отчёта и корпуса. Исторические индексы сравниваются по подготовке,
полные inference-контракты workers по-прежнему проверяются строго.
CUDA-инициализация в Laya-тестах замокана; запуск checkpoint на RTX они не подтверждают.
В чистой копии файлов Git с новыми исходниками прошли **169 CPU-тестов, 0 ошибок
и пропусков**, включая 12 Laya-тестов на маленькой случайной модели.
Offline пересобраны восемь smoke и три screening-отчёта: прежние результаты совпали;
только старый Laya-отчёт дополнен `precision_status=historical_unrecorded`.
На момент CPU-проверки реальная GPU-проверка патча ещё не выполнялась;
последующий RTX 4090 smoke описан выше, RTX 5090 остаётся непроверенной.
Свидетельства 4 ноября ниже остаются историческими и не являются approval нового кода.
[Проверка 7 ноября и SHA256 исходников](../results/u1_handoff/native_precision_2026-11-07.json).

Для Open подготовлен производный профиль v2: новый manifest фиксирует обновлённый
сборщик. Исходные сообщения, все token-индексы и списки бакетов сохранены;
переиндексация Laya не требуется. Опубликованный HF snapshot, lock и approvals
не менялись; профиль v1 и его результаты не перезаписывались.

## Реализовано и проверено на CPU

- Восемь закреплённых контрактов; собственные классы Koala/Laya/Shield, необязательные именованные scores.
- Baseline-only и сравнение через внешний адаптер; готовый артефакт с хешем и происхождением.
- Импорт speed-корпуса и пересечения полных входов; отдельный quality-набор и явный mapping.
- Уникальные flips, направления, macro по бакетам; confusion matrix, accuracy, macro-F1, FPR/FNR и coverage по срезам.
- Свежие процессы, timeouts/частичные архивы, offline report и baseline-таблица с группами совместимости.
- Тестовый внешний адаптер: 400 ID, четыре изменения = 1%; квантование не отклоняется только из-за flips. Фиктивные измерения не становятся GPU-pass.
- Настоящий quality-worker с CPU fixture: ошибки/over-limit сохраняются; закрытые тексты отсутствуют в архиве.

## GPU-smoke

Новая реализация v2 проверена отдельно на Kaggle T4 GPU 0 с неизменённым lock. Финальная сборка launcher v5: `75fe9590b762cab92de058a7335ff066a2aa808045b9b3f218d28e9680ac53a9`, каталог `u1-handoff-15f88e75`. Выделялись T4 ×2, работала только GPU 0. Полные screening не запускались.

[Приватный Kaggle launcher](https://www.kaggle.com/code/avxofi/u1-handoff-adapters-smoke-v1/edit). После проверки скачанного архива сессия остановлена. Суффикс v1 в URL относится к имени notebook, а не версии итоговой сборки.

Время выше — весь worker с загрузкой/подготовкой/проверками, не latency одного запроса. У прошедших моделей проверены фактические входы, короткий/длинный текст каждого обязательного бакета, A→B→A, точная граница и отказ на превышении, реальные GPU kernels, полный запрос и сбор памяти.

и не включены в эту Git-публикацию. Сумма общего архива: `defd7eb3d549bea11d47cc9cd981e79eb1990c33a76fd8010045de6c03a59106`.

- 208 CPU-тестов: OK, один пропущен по условию среды. Отдельно валидированы nbformat, синтаксис и 58 встроенных файлов.
- Финальные восемь отчётов пересобраны локально без GPU и совпали с архивными. Хеши исходников совпали с текущим кодом.
- Старые три сравнения прочитаны в общую таблицу; исходные summary и численные p50/p95 не изменились.
- Предыдущие неудачные попытки сохранены: сбор размера требовал неиспользуемые файлы HF-репозитория; проверка generate не учитывала удаление маски из единиц; whitelist ответа не включал public_confidence GLiNER. Исправления проверены повторным smoke, а не переписыванием старых результатов.
- Предупреждение host sitecustomize/wrapt осталось зарегистрированным ограничением. Lock не менялся.

Для Laya требуется отдельно согласовать SDK/среду и повторить smoke; для ShieldGemma — предоставить доступ в runtime и повторить smoke. Эти строки не считаются совместимыми с общей средой до успешной проверки.
