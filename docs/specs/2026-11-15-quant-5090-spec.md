# Спека: FP8-квантование gliner-guard-omni и HiveTraceGuard-Pro на RTX 5090

Дата: 2026-11-15. Ветка: `research/quantization` (новые ветки не создаём, push — только по команде).

## Цель

Измерить **чистый эффект квантования**: скорость и качество FP8-кандидатов относительно эталона
**bf16 + `torch.compile`** (без CUDA-графов и других правил) на RTX 5090, в среде, идентичной коллегам (У1 v4).

## Модели

| Ключ | Репозиторий | Ревизия | Почему |
|---|---|---|---|
| `gliner` | `hivetrace/gliner-guard-omni` | `763f8aa9a7714dd2c3264f3751acdd5d854c5ac4` | информативный encoder на хвостах (FNR 10–17% на T4) |
| `hive` | `hivetrace/HiveTraceGuard-Pro` | как в `configs/v4/hive.json` У1 | decoder, продуктовый домен |

Koala, Llama-Prompt-Guard-22M, Laya — не берём (на наших данных неинформативны или англоязычные).

## Варианты

| Вариант | Описание | Когда |
|---|---|---|
| `bf16c` | bf16, `torch.compile` (dynamic, fullgraph), без квантования — **эталон** | этап 1 |
| `fp8` | torchao `Float8DynamicActivationFloat8WeightConfig`, granularity per-row, все `nn.Linear` тела модели; головы/`lm_head` — bf16; + compile | этап 2 |
INT8, TurboQuant и `fp8_mixed` (подбор чувствительных слоёв) — не делаем (решение 2026-11-17).

## Измерения

- **Скорость** — протокол У1 v4 без изменений: `baseline` для `bf16c`, `search` для каждого кандидата, `confirm`
  для лучшего. Сетки — пресеты У1: gliner `B1:[1,256]`; hive `B1:[1,64] B2:[1,32] B3:[1,16] B4:[1,8]`.
  Корпус — общий `role-v4` (индексы строятся штатным `prepare-data` У1).
- **Качество** — режим `quality` У1 v4 на **tails_v2** (`AutotuneGuardrails/tails`, тег `v2`, 7 121 строка),
  `quality_batch_sizes: [1]`, baseline = `bf16c`, candidate = кандидат. Срезы: `technique`, `lang`, `benchmark`, `tail`.
- **Анализ качества** (офлайн, наш скрипт) по `predictions.jsonl`: смены вердикта (хуже/лучше относительно
  разметки), McNemar (точный) + поправка Holm по техникам, bootstrap 95% CI для доли смен, ΔFNR, ΔFPR;
  для каждой техники — MDE и граница при нуле смен (3/N), как обещано в README tails_v2; coverage.
- **Критерий «нет значимой деградации»:** объединённый McNemar по сменам в худшую сторону незначим (α=0.05) и ни
  одна техника не значима после Holm. Отчёт по техникам — диагностика с их MDE.

## Среда

- Профиль **`team-rtx-quant`** = `env/team_rtx.lock.json` У1 **плюс ровно `torchao`** (одна версия, совместимая
  с `torch 2.11.0+cu130`); остальные 97 пакетов не меняются. Установка как у У1: `--no-deps --require-hashes`.
- Под без сетевого тома: Volume Disk 50 ГБ (`/workspace`), Container Disk 30 ГБ. Всё наше — в `/workspace/u2-*`,
  `HF_HOME=/workspace/u2-hf`. Сетевой том коллег не подключаем.
- Результаты каждого этапа копируются на Mac (`scp`) до начала следующего.

## Изменения кода (только аддитивные)

1. Влить `origin/results/haloguard-gliner-u1` (`100ce48`) в `research/quantization`.
2. Профиль `team-rtx-quant` в `u1_benchmark/environment.py` и `tools/benchmark.py setup`.
3. Пакет `u2_quant/`: квантование, внешний адаптер (обёртка над `NativeAdapter` У1), генератор конфигов,

4. Скрипты пода `scripts/u2_pod_setup.sh`, `scripts/u2_pod_run.sh`.

Существующие функции У1 (`quality.metrics`, `quality.agreement`, отчёты) не меняются — их используют скоростные отчёты.

## Вероятности HiveTraceGuard

Адаптер для `hive` вызывает тот же `generate(max_new_tokens=1)` с `output_scores=True` и возвращает
`scores = softmax(logit_safe, logit_unsafe)` (`score_type: probabilities`). Одинаково у эталона и кандидата.

## Вне скоупа

CUDA-графы, правила kekwak, INT8, TurboQuant, Koala, изменение протокола скорости У1, push в ветку У1.
