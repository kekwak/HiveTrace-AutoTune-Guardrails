# Протокол измерений У1: schema 4

Актуально на 12 ноября 2026. Команды находятся в [инструкции](u1_handoff.md).
Версии конфигурации, результатов, данных и протокола фиксируются раздельно.
Актуальный измеритель отклоняет старые конфиги/архивы; оригиналы и
[протокол v0.1](measurement_protocol.md) не изменяются. Миграция истории отдельно.

## Контракты и среда

Baseline и candidate задаются полностью, без наследования: adapter, weights,
tokenizer/SDK-assets, template, preparation/scoring, execution. Восемь пресетов
не ограничивают checkpoint. Параметры применяются либо отклоняются явно; нет
автоматической смены backend, dtype, усечки или CPU fallback.
CPU-preparer и inference используют одну подготовку. Preparation identity
отделена от task/scoring и provenance исполнения.

Engineering сохраняет веса, задачу, фактические входы и precision. Parameter
допускает заявленные вычислительные изменения при той же задаче и входах.
Quantization фиксирует связь артефакта с baseline без автоматического quality-approval.
Laya сохраняет native_sdk AMP; режим не выбирается по названию GPU. Precision
не меняется между workers варианта. Для ORT разрешены только доказанные служебные
CPU-операции metadata-cpu-v1.

До workers фиксируется неизменяемый resolved_run.json: эффективные настройки,
источники, данные/ID/индексы, планы, seed и критерии. Наблюдаемые GPU/dtype/AMP/backend
записываются отдельно. Linux/Python 3.13, прежний lock, GPU 0, concurrency 1.
RTX 4090/5090/T4 группируются раздельно. Model seed 42, seed порядка по умолчанию 17;
два CPU-потока, eval/inference_mode, TF32 off, cuDNN benchmark off,
deterministic algorithms warn_only. Каждая сторона/серия в свежем процессе,
общий лимит 10 часов. Битовая воспроизводимость не обещается.

## Данные и батчи

Общий ролевой корпус, нативный формат моделей; text импортируется как user.
Бакет по полному входу до padding: B1 1–512, B2 513–1024, B3 1025–2048,
B4 2049–4096. Обязательные бакеты/лимиты задаются конфигом. Полный командный
прогон требует 400 уникальных эффективных входов на бакет; меньше только smoke/pilot.
Различия проигнорированного контекста не создают новые эффективные входы.

Baseline/candidate получают одинаковые ID, сообщения, token IDs/маски, батчи и
порядок. Индексы фиксируются до сравнения. Кандидат не пересобирает бакеты.
Корпус скорости не размечен и не представляет production-трафик.

Любой целый B от 1 до N. Без сетки B=1. Основная серия содержит
max(100, ceil(N/B)) полных батчей из одной циклической случайной перестановки,
без сортировки по длине. Все N покрыты; внутри батча повторов нет; числа
появлений ID отличаются максимум на один. Seed зависит от seed/phase/block/bucket.
В паре планы одинаковы; search читает планы reference. Повторы не независимы.

Разреженные пресеты: encoder B1 1/256; decoder B1 1/64,
B2 1/32, B3 1/16, B4 1/8. Сетки задаются только конфигурацией; это не
утверждение вместимости всех моделей. Промежуточные размеры можно добавить.
Reference для search должен соответствовать всей выбранной сетке.
Минимум 100 батчей в серии остаётся: увеличение B увеличивает число обработок,
а не гарантирует сокращение времени прогона. Сокращение числа ячеек не является
измеренным wall-clock ускорением инструмента.
Padding только до максимума внутри батча; без усечки, фиктивных входов и
padding до границы бакета. Generation использует left padding; scoring выбирает
последний содержательный токен. Generated tokens включают собственный EOS,
но не последующий padding, в том числе при одинаковых pad/EOS ID.

## Стадии

Preflight один раз на вариант/ячейку: реальные входы и маски, short/long/mixed,
повтор после другого входа, граница/отказ превышения до forward, конечность/парсинг,
backend/precision. Smoke не запускает основные серии. Свежие latency workers
проверяют evidence и готовят необходимые формы вне таймера.

| Режим | На ячейку | Значение |
| --- | --- | --- |
| Baseline | A/A две пары по 30, три основные серии | Полный reference, не ускорение |
| Search | Только candidate, три серии по планам reference, без A/A | Предварительное сравнение |
| Confirm | A/A две пары по 30, три новые A/B-пары с AB/BA | Парное подтверждение |
| Pilot | Одна серия/пара по 12 батчей, без A/A | Проверка пути, без pass |

Перед каждой стороной/серией 20 прогревов. Search не загружает baseline.
Reference должен быть полным, не smoke/pilot, совместимым по baseline-конфигу,
входам/планам, исходникам, GPU/VRAM, драйверу/CUDA, пакетам, вычислительным
настройкам и мониторингу. UUID/host/session/время сохраняются; одинаковая среда
не исключает дрейф. Baseline evidence копируются для автономного отчёта.

Confirm отклоняет baseline-ref и заново измеряет обе стороны. Это не независимая
репликация. Обновление reference запускается явно. OOM/unsupported сохраняются
по ячейке; остальные продолжаются в свежих процессах до таймаута, без уменьшения
батча или изменения dtype. Plan показывает точные объёмы без моделей/GPU.

## Скорость и приёмка

Таймер: GPU sync → исходные сообщения → нативная подготовка, токенизация/collation,
GPU-вычисления → scores/вердикты на CPU → GPU sync. Готовые тензоры/ответы не
подменяют обработку текста. Загрузка, экспорт, компиляция, backend proof,
прогрев, запись логов и профайлер вне таймера. Новая компиляция внутри серии
запрещает вывод об ускорении.

Главная метрика pooled p95 всего батча в ячейке, p50 дополнительная.
Throughput = обработки / суммарное измеренное время. Latency/B не является
задержкой запроса. Полезные/padded tokens и доля padding показываются отдельно;
очередь сервинга и ожидание наполнения батча не моделируются.

Снижение = 1 - candidate/baseline. Confirm: парный блочный bootstrap 2000/seed42,
без ресэмплинга отдельных запросов. Положительное направление во всех трёх блоках,
верхняя граница отношения ниже 1; эффект превышает A/A envelope и дрейф.
A/A envelope = max(max(r,1/r)-1); дрейф = max(p95 блока)/min(p95 блока)-1.
Шум/неполнота не становятся pass; устойчивое замедление сохраняется.

Engineering требует строго >20%, parameter >10% снижения p95 во всех обязательных
ячейках, ноль flips и нестабильных повторов. Search показывает непарные
предварительные отношения без confirm_pass и парных интервалов.
Baseline показывает p95 серий, A/A, дрейф и блочные интервалы; baseline_complete
означает комплектность, не стабильность. Три серии дают ограниченную оценку.

Flips считаются по уникальным общим ID внутри ячейки, направления и нестабильность
отдельно. Single→batch использует сохранённые измерительные ответы, не preflight.
Quantization не имеет lossless-gate; макросредние долей изменений по бакетам
не означают сохранение качества. «Ускорение во всей сетке» требует положительного
подтверждённого эффекта и шумовых проверок везде, но не достижения 20%/10%.
Полнота, пороги, вердикты, качество раздельны. Необъявленные ячейки not_scheduled.

## Совместная память и профили

Обязательных memory-workers нет. Torch allocated/reserved в том же worker:
setup отдельно, после прогрева reset peak counters и inference. Empty_cache
не вызывается. Один длительно работающий [nvidia-smi](https://docs.nvidia.com/deploy/nvidia-smi/index.html)
с --loop-ms=100 на worker
снимает память GPU-процесса с PID/GPU UUID, timestamps/фактическими интервалами;
N/A, некорректные samples и пропуски сохраняются. Опрос/запись вне тела таймера,
но косвенный overhead проверяется отдельно.

Setup/inference, выборочный пик процесса, Torch counters и размер артефактов
разделены; Torch не заменяет память ORT. Samples не гарантируют абсолютный пик.
Ошибка sampler не скрывает latency/исходную ошибку; память unavailable/partial.
Метод мониторинга сравниваемых сторон одинаков.

Однократная техническая проверка GLiNER/Open B1×1: три off/on пары по 30 одинаковых
запросов, AB/BA после прогрева. Для p50/p95 верхняя граница 95% блочного интервала
on/off ≤1,05. При шуме/неуспехе monitoring unvalidated, метод не переключается сам;
подтверждённое ускорение не заявляется. Проверка не повторяется перед кандидатом.

Short/long traces только явным profile-trace, вне latency и не условие скоростного
pass. Backend-proof остаётся preflight. Fused kernels не атрибутируются только по
подстроке имени.

## Качество и артефакты

Quality не читает speed-корпус. Target, объект разметки, slices и native-label mapping
явны; метку ответа нельзя сопоставлять с оценкой запроса HaloGuard.
Quality_batch_sizes по умолчанию [1], любой положительный integer; один проход
с неполным хвостом без повторов. Каждый размер/вариант в свежем worker,
без A/A, скоростных серий и memory-проходов. Неприменимость/over-limit/ошибки
сохраняются в coverage.

Confusion matrix, accuracy, macro-F1, для явной бинарной задачи FPR/FNR, N/срезы,
null для неопределённых знаменателей. Парные и single→batch сравнения имеют
явный общий знаменатель. Автоматического quality-approval нет.
Speed-набор не даёт accuracy/F1 или гарантии safety.

Архив: resolved snapshot, исходники, планы, safe outputs, raw latency, memory
samples, setup/backend durations, статусы/ошибки и опциональные traces.
Закрытые тексты, сообщения, промпты, токены доступа, веса и venv исключены.
Inline-промпты конфигурации в публичном snapshot представлены SHA256; полный
исполняемый конфиг остаётся в .private с проверкой целостности. Исходники адаптера
архивируются, поэтому секреты и закрытые примеры в них встраивать нельзя.
Частичные результаты сохраняются, существующий ZIP не перезаписывается.
Report/table читают JSON/evidence без HF, исходного корпуса или исполнения
архивного кода; разные среды/данные/протоколы не смешиваются.

Старые smoke и CPU-подготовка не подтверждают новые GPU-пути. Приёмка редакции:
CPU-тесты и воспроизводимые индексы, затем восемь верхних baseline-smoke-ячеек
на 5090 и проверка overhead. Полные baseline/search/confirm в этап не входят.
