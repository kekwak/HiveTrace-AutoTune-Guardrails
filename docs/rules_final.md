# Финальный набор правил

Только правила, которые дали выигрыш на замерах, и условия их включения. Условия проверяются кодом (`rules/conds.py`), подробности правил — в `optimizations.md`.

## Когда что включать

| Правило | Включать, если | Параметры | Эффект (p95) |
|---|---|---|---|
| **U4** `torch.compile` | всегда | любой batch; разрывы графа (`torch._dynamo.explain`) снижают эффект | batch 16: основной выигрыш, −23…−40% у энкодеров |
| **U1** CUDA graph по бакетам длин | `torch.cuda.is_available()` и batch 1 | только вместе с U4. Входы > 2048 токенов у декодера — только вместе с быстрыми ядрами attention (C7), иначе медленнее | batch 1, короткие входы: −70…−87%; batch 16: ≈ 0 |
| **C7** быстрые ядра linear attention | `"linear_attention" in cfg.layer_types` или есть `*GatedDeltaNet`, и импортируется `fla` | обязателен при входах > 1024 токенов | HaloGuard B4: +17% → −30% |
| **C3** lm_head по двум токенам | `model.can_generate()`, есть `lm_head`, вердикт за один forward | — | +1–2% поверх U1+U4 |
| **C8** кэш относительных позиций DeBERTa | `any(hasattr(m, "get_rel_embedding") for m in model.modules())` | — | batch 1: KoalaAI −24% → −37% |
| **C12** слить Q/K/V и gate/up | у модуля есть отдельные `q_proj/k_proj/v_proj` (или `gate_proj/up_proj`), все `nn.Linear` с одинаковым bias | — | +1–2% |
| **C9** веса в fp16/bf16 вместо autocast | веса fp32, forward идёт под `autocast` fp16/bf16 | — | batch 1: Laya −11% сам по себе |
| **C13** один forward вместо `generate(max_new_tokens=1)` | эталон зовёт `generate` с `max_new_tokens == 1` | нужен как основа: без него к модели не применить U1/U4 | ≈ 0 сам по себе |
| **C4** вердикт по первому токену | эталон зовёт `generate` с `max_new_tokens > 1`, и первый токен совпадает с вердиктом полного ответа | — | p50 −14 мс, p95 ≈ 0 |

## Не включать

| Правило | Почему |
|---|---|
| **C2** кэш префикса | На baseline v4 замедляет: HaloGuard +10…+18%, HiveTraceGuard-Pro до +72%. У HiveTraceGuard-Pro ещё и меняет вердикты (4 из 1600) |
| **U3** убрать синхронизации | При batch > 1 нельзя: маска нужна для паддинга. При batch 1 выигрыш ≈ 0 |
| **U1+U4 через штатный `generate` HF** (статический кэш + `reduce-overhead`) | Open: на 13–26% медленнее baseline |

| Модель | Набор | batch 1 | batch 16 | Вердикты |
|---|---|---|---|---|
| Llama Prompt Guard 2 | U1+U4+C8+C12 | −71% | −40% | 0 |
| GLiNER Guard | U1+U4+C8+C12 | −54% | −39% | 0 |

| HaloGuard | U1+U4+C7 | −87 / −66 / −42 / −30% | — | 0 |
| ShieldGemma | U1+U4+C3 | −73 / −52 / −31 / −31% | — | 2 пограничных из 1600 |
| HiveTraceGuard-Pro | C13+U1+U4 | не измерено без C2 | — | — |
| OpenGuardrails | C4 | p50 −14 мс, p95 ≈ 0 | — | 0 |

Для декодеров значения указаны по бакетам B1 / B2 / B3 / B4 (до 512 / 1024 / 2048 / 4096 токенов).

**Источники.** Энкодеры при batch 1 мерились старым измерителем (`2b09a3e`, `results/u3_rules/2026-11-10-encoders-rtx5090`). Всё остальное — измерителем v4 (`100ce48`) в режиме `search`.

**Что ещё не подтверждено.** HaloGuard мерился с C2. Без C2 он должен быть не хуже, но это надо проверить. Все цифры v4 предварительные: нужен `confirm`.
