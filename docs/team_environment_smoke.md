## Повторное воспроизведение

[Ноутбук](../notebooks/team_environment_smoke.ipynb): чистая Kaggle/Colab Linux-сессия с Python 3.13, T4 и Internet → Run All. Локальный клон не нужен. Устанавливается отдельный venv; PyTorch основного notebook не переустанавливается, перезапуск ядра не требуется. Скачивание зависимостей и весов требует нескольких ГБ диска. Лимит запуска — 90 минут, не обещание длительности; сами проверки короткие, но установка/JIT могут занять основное время.

Исправление после `team_env_smoke_7b004450`: первый запуск остановился на `ensurepip` при создании venv, до установки и всех GPU-проверок. Теперь используется `venv --without-pip` и существующий host pip с явным `--python <venv>/bin/python` для install/check/freeze. Проверяется изоляция venv. Способ [поддерживается pip с 22.3](https://pip.pypa.io/en/stable/topics/python-option/); в присланном runtime pip 24.1.2. Локально добавлен реальный offline-тест установки тестового wheel только в pip-less venv, без изменения host.

## Результат 64014dfd и исправления

Запуск занял 365 секунд: установка, PyTorch CUDA и ORT CUDA MatMul прошли. В ORT-профиле один CUDA-узел, CPU-узлов нет. Это подтверждает совместимость на уровне примитива, не всего GLiNER encoder и не FLA. Модельные стадии остановились:

- GLiNER: третий синтетический текст оканчивался пробелом. `SchemaTransformer._normalize_text()` добавляет точку, если последний символ не `.`, `!` или `?`. Строгая проверка сохранности текста верно заметила изменение. Теперь предложения соединены пробелами без завершающего пробела; проверка не ослаблена. Совместимость нормализации проверяется CPU-тестом реального GLiNER2.
- HaloGuard: Transformers 5.20.1 больше не имеет `is_fast_path_available` и старых per-layer bindings. В новой версии функции вызываются через module-global dispatch; optional FLA может выбираться автоматически. Новый `followup/team_halo.py` явно вызывает исходные PyTorch-функции (без optional-wrapper) для reference и только FLA Gated DeltaNet для ускоренного варианта. Convolution и norm остаются reference; hub kernels выключены. Вызовы учитываются и проверяются для **всех** вариантов, глобальные bindings восстанавливаются после каждого forward, в том числе при исключении.
- Из дочерних процессов убраны унаследованные `PYTHONPATH/PYTHONHOME`, чтобы host `sitecustomize` не внедрялся в venv. В присланном логе он выдавал ошибку `wrapt`; это предупреждение не было причиной двух модельных сбоев.
- При сбое следующего входа сохраняются уже полученные scores и индекс текущего текста. Frozen-source и прежние approvals не менялись; новый адаптер не наследует их допуск.

Исправления проверены запуском 45555111, описанным выше. При необходимости воспроизведения ноутбук создаёт новый venv; можно использовать прежнюю T4-сессию с достаточным свободным диском, поскольку это не независимый подтверждающий benchmark. Новая VM для этого smoke не обязательна.

## Что сохраняем

База коллег: torch 2.11.0+cu130 / Transformers 5.20.1. По решению пользователя сохраняем наши версии ORT 1.23.2, GLiNER2 2.1.0, FLA и fla-core 0.4.2; ONNX 1.20.1 взят из рабочего GLiNER-экспорта. Сопутствующие версии и CUDA 12 runtime-библиотеки ORT перечислены в [паспорте](../env/team_base.json). CUDA 13 NVRTC 13.0.88, cuDNN-cu13 9.19.0.56 и Triton 3.6.0 закреплены в установочном рецепте по артефактам команды.

ORT этой версии использует CUDA 12-библиотеки, PyTorch — CUDA 13. Обе группы устанавливаются явно и проверяются в одном процессе. Импорт или список доступных providers не доказывают совместимость; мы проверяем реальный CUDA MatMul и размещение узлов. [Требования и preload ORT](https://onnxruntime.ai/docs/execution-providers/CUDA-ExecutionProvider.html). При конфликте остаются лог и blocker; не обновляем ORT, не откатываем Transformers и не переключаемся на CPU автоматически.

## Что проверяет Run All

1. GPU и Python до установки; новый venv, pip dry-run, установка точных прямых зависимостей, pip check и список разрешённых версий. CUDA PyTorch ставится только внутрь venv. Host-драйвер не меняется.
2. PyTorch CUDA: совпадение версий, NVRTC workaround коллег, cuDNN, маленький MatMul на T4.
3. ORT CUDA: MatMul с запретом CPU fallback; результат сверяется с NumPy, проверяется фактический provider по профилю.
4. GLiNER: FP32 eager и encoder в ORT через настоящую голову, три текста + повтор первого, проверка input hashes и численных ответов. Для полного GLiNER сохраняется проверенная политика служебных CPU-операций, не строгий запрет всех CPU-узлов toy-графа.
5. HaloGuard: FP32 reference, FP16 reference и FP16 FLA, прежний prompt/scoring и checkpoint; счётчик реальных вызовов FLA, небольшая проверка ответов и повтора.

Если ORT MatMul не прошёл, GLiNER eager и HaloGuard всё равно проверяются, экспорт GLiNER пропускается. Ошибка базового PyTorch CUDA останавливает модельные проверки. Старые исходники встроены без изменения; новый адаптер Halo находится отдельно и включён в checksum ноутбука. Версии библиотек и checkpoint не меняются автоматически.

## Результат

Скачать **`team_env_smoke_*.zip`**, в том числе при ошибке. Папка `_team_env_smoke_*_venv` остаётся на runtime и в архив не входит. Веса и ONNX-экспорты исключены; ORT-профили сжаты. Архив обновляется после каждой проверки; потеря самой VM не перехватывается.

- `status.json`: `passed` только при завершении всех проверок; `partial` при сбое отдельных стадий, `failed` при ошибке подготовки. `environment_validated` относится только к перечисленным smoke-проверкам.
- `installation/`: dry-run/install reports, разрешённые версии, pip check, исходный паспорт. Это материал для будущего lock, не заранее обещанный полный lock.
- `stages/`: фактические версии и пакеты, ошибки/таймауты, input hashes, scores, численные отклонения и backend evidence. Наличие CUDA 12 и 13 фиксируется явно.

**Не выполняются:** latency/throughput benchmark, compile, 300-примерная регрессия, holdout и оценка safety. Допуски smoke (max Δp 0.001 FP32 / 0.05 FP16, без смен меток на этих трёх входах) служат для грубой диагностики, не для допуска конфигурации в production. Успех smoke не переносит прежние проценты ускорения на новое окружение.

Комплект проверяется CPU-тестами и nbformat; T4-запуск 45555111 подтвердил перечисленные модельные пути. Дополнительно новый адаптер проверен с маленьким локальным checkpoint Transformers 5.20.1 на CPU. Исторические notebooks, среды и approvals не изменены. Дальше идём к общему протоколу и runner, не повторяя сейчас полный benchmark.
