К синку 30 октября 2026. Основа выбрана из среды Koala/OpenGuardrails; это предложение У1, не решение за всех владельцев моделей. [Паспорт и источники](../env/team_base.json), [очередь работ](u1_protocol_plan.md), [протокол v1 для обсуждения](measurement_protocol_v1.md).

## Быстрый Старт В Kaggle / Colab

Для своей работы используйте **[team_environment_skeleton.ipynb](../notebooks/team_environment_skeleton.ipynb)**. Достаточно загрузить один файл: lock, SHA256 и вспомогательный код встроены, клон репозитория не нужен.

1. Kaggle: загрузить notebook, выбрать accelerator T4, включить Internet. Colab: загрузить notebook и выбрать T4. Lock поддерживает только Linux x86_64 / Python 3.13; первая проверка остановит неподходящий runtime до установки. Kaggle — проверенная площадка исходного smoke; Colab и новый skeleton на GPU ещё не проверялись.
2. Выполнить Run All. Шапка создаёт отдельный pip-less venv, устанавливает **из полного lock** с проверкой hashes, сверяет все 96 версий и выполняет CUDA MatMul. Основной kernel/PyTorch не меняется, restart не нужен. Полная установка требует нескольких ГБ; лимит установки 60 минут.
3. Заменить пример в ячейке `%%writefile experiment.py` своим кодом. Выполнить эту ячейку и следующую `SESSION.run(...)`. Повторно запускать установку не нужно; повтор всего Run All создаёт новое окружение и отдельный рабочий каталог.
4. Результаты писать в `Path(os.environ['RESULT_DIR'])`. Каждый запуск — свежий процесс Python из venv с отдельной папкой, копией исходника, stdout, статусом и паспортом. Переменные Python между запусками не сохраняются. Дополнительные `.py`-модули в рабочей папке можно импортировать; их копии также сохраняются.
5. Последняя ячейка скачивает архив в Colab или показывает файл в Kaggle Output. Архив обновляется после установки и каждого запуска, включая ошибки/таймауты. Лимит пользовательского запуска по умолчанию 60 минут, меняется аргументом `timeout` в секундах.

**Ключевое отличие:** `%%writefile` только сохраняет код; следующая ячейка запускает его нужным Python. Обычный `import torch` в notebook-ячейке и `!python experiment.py` используют host-runtime, не наш venv. Не устанавливайте туда зависимости через `%pip`/`!pip` в обход lock. Дополнительные пакеты нужно согласовать и закрепить отдельно.

Файлы датасетов доступны по абсолютным путям, например `/kaggle/input/...`; они не копируются в архив автоматически. Веса, скрытые файлы и venv исключены; лимиты архива — 50 MiB на файл и 200 MiB суммарно, список пропусков находится в `archive_contents.json`. Большие traces/веса скачивать отдельно. Токены задавать через secrets платформы, не записывать в код/stdout: они входят в архив. Список всех переменных окружения не собирается.

В каждом процессе проверяются пакеты, CUDA и применяется seed 42, два CPU-потока, TF32 off, deterministic warn_only, NVRTC preload. Hub kernels отключены. Если используете ORT, перед session нужен `onnxruntime.preload_dlls(cuda=True, cudnn=True, directory='')`; корректность размещения вашего графа на GPU необходимо проверить отдельно. Skeleton не навязывает модель, prompt/scoring или оптимизацию и не реализует протокол измерений.

При неудачной установке пользовательский код не запускается, архив остаётся доступен. Сначала изучить ошибку; для новой попытки начать с ячейки создания рабочего каталога. Существующий неполный venv автоматически не чинится. Предупреждение sitecustomize/wrapt остаётся известным ограничением, не исправляется добавлением пакетов вслепую.

**Статус:** новый skeleton прошёл CPU-тесты, проверки формата и встроенных исходников. Реальная установка именно из lock и первый запуск на T4 ещё впереди. Это не повтор больших экспериментов: по умолчанию выполняется только пример MatMul.

## Что проверено

`team_env_smoke_45555111` успешно завершился на Kaggle T4 за 625 секунд, включая установку и загрузки. Проверены PyTorch CUDA, ORT CUDA MatMul, GLiNER FP32 eager/ORT со штатной головой и HaloGuard FP32/FP16 reference/FP16 linear-only FLA. По три синтетических входа и повтор первого; это не оценка качества и не benchmark. [Численные результаты и backend evidence](team_environment_smoke.md).

Фактические Python 3.13.15, torch 2.11.0+cu130, Transformers 5.20.1, CUDA 13.0, cuDNN 91900, driver 580.178.04. Для PyTorch сохраняются CUDA 13 библиотеки, для ORT 1.23.2 — отдельно закреплённые CUDA 12 библиотеки и явный preload. Они успешно работали в одном процессе GLiNER. Не удалять одну группу как «дубли»: это разные runtime-зависимости. GLiNER2 2.1.0, FLA/fla-core 0.4.2 сохранены.

GLiNER ORT использует CUDA для вычислений и ограниченные служебные CPU-операции по проверенной политике `metadata-cpu-v1`, а не CUDA-only граф. Halo использует отдельный адаптер для Transformers 5.20.1: автоматический выбор optional kernels отключён, reference и FLA различаются явно. Conv/norm не ускоряются одновременно с linear attention.

**Не проверено:** повторное развёртывание из нового lock, compile на новой базе, остальные модели команды, скорость и качество новой среды. Владельцы остальных моделей выполняют свои короткие smoke перед принятием базы.

## Что закреплено

- [team_environment.lock.txt](../env/team_environment.lock.txt): 96 точных wheel URL и SHA256. Все прямые и транзитивные пакеты из изолированной успешной установки, без host-пакетов. Это полный набор для **Linux x86_64 / CPython 3.13**, не универсальный lock для macOS, ARM или другой версии Python.
- [team_environment.lock.json](../env/team_environment.lock.json): имена, версии, URL, SHA256, исходная платформа, hash install report и четырёх worker inventories. Все четыре inventory точно совпали с 96 пакетами отчёта; лишних/отсутствующих пакетов нет.
- [team_base.constraints.txt](../env/team_base.constraints.txt): только прежние прямые ограничения; не заменяет полный lock.

Lock получен из структурированного `installation/install.json`, не парсингом вывода pip. Hash берётся из install report, повторное скачивание wheel в этой итерации не выполнялось. `--require-hashes` проверит скачанные байты при установке. Lock не фиксирует драйвер, OS image, CPU/RAM, доступность VM и веса моделей: они отдельно записываются в паспорт; model revisions находятся в адаптерах. Контейнер не создавался.

## Установка Из Lock

Из корня клона проекта на Linux x86_64 с Python 3.13 и доступом в интернет. Host pip должен поддерживать `--python` (>=22.3; в исходном запуске 24.1.2). Нужен свободный диск для нескольких ГБ библиотек и весов. Не выполнять на macOS, не менять host CUDA PyTorch и не обновлять версии по ходу установки.

```bash
python --version
python -m pip --version
nvidia-smi
python -m venv --without-pip /tmp/u1-team-env
python -m pip --python /tmp/u1-team-env/bin/python install --no-deps --require-hashes --only-binary=:all: -r env/team_environment.lock.txt --report /tmp/u1-team-env-install.json
python -m pip --python /tmp/u1-team-env/bin/python check
python followup/team_lock.py verify --python /tmp/u1-team-env/bin/python
```

Использовать новый, ещё не существующий путь venv. `--no-deps` намеренно запрещает повторное разрешение: все 96 зависимостей уже перечислены. Затем `pip check` проверяет зависимости, а verifier требует точного набора пакетов без extras/дрейфа. При несовместимом wheel или недоступном URL остановиться и сохранить ошибку; не заменять пакет на ближайшую версию. Не добавлять pip внутрь venv: им управляет host pip, иначе строгая проверка увидит лишний пакет.

Эти команды проверяют установку и inventory, **не запускают модель и не подтверждают GPU-совместимость нового развёртывания**. Исходный успех относится к установке из прямых pins с сохранённым install report. Повтор из lock пока имеет статус `lock_redeployment_verified=false`.

## Воспроизведение Модельного Smoke

[Самостоятельный notebook](../notebooks/team_environment_smoke.ipynb): Kaggle/Colab Linux Python 3.13, T4, Internet → Run All → скачать `team_env_smoke_*.zip`, включая частичные результаты при ошибке. В успешном запуске использована одна видимая GPU, хотя у VM было две T4. Ноутбук не запускает оплачиваемые ресурсы самостоятельно.

**Важно:** существующий notebook создаёт собственный venv и использует исторический рецепт прямых pins, а не только что установленный `/tmp/u1-team-env` и не новый полный lock. Его воспроизведение проверяет прежний путь, но не является повторным развёртыванием из lock. Сейчас не меняем успешно проверенную установочную логику; подключение lock и GPU-проверка такого пути — отдельный следующий шаг. Уже пройденный smoke повторять перед синком не требуется.

Seed 42, два CPU-потока, `eval`/`inference_mode`, TF32 и cuDNN benchmark выключены; deterministic algorithms в `warn_only`. CUDA 13 NVRTC builtins загружаются явно, ORT — через CUDA 12 preload. Не обещаем побитовую детерминированность.

## Известное Ограничение

В venv осталась ошибка host `sitecustomize: No module named wrapt`. Очистка унаследованных PYTHONPATH/PYTHONHOME её не устранила. Workers продолжили работу; `pip check`, точные версии и модельные проверки прошли. Причина подключения startup-кода пока не установлена. Не устанавливаем wrapt вслепую и не отключаем startup-механизмы. Для разбора нужны происхождение `sitecustomize` и пути импорта на исходной платформе; это не повод повторять performance-эксперименты.
