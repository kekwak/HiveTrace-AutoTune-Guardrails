## Узкие места

1. **Attention.** Самая большая доля времени, растёт с длиной входа. PyTorch выбирает медленный вариант attention (`_scaled_dot_product_attention_math`) и считает его в fp32. Причина: у модели 16 голов Q и 8 голов KV, а быстрые варианты на T4 такое не поддерживают. Если продублировать головы KV, быстрый вариант работает (`check_sdpa.py`: 11.1 → 0.6 мс на один слой при 1441 токене).
2. **Много мелких операций вне attention** (нормализации, RoPE, активации) — около 24% времени на коротких входах. Каждая запускается отдельным ядром.
3. **Запуск ядер со стороны CPU** — около 16 мс из 78 на коротком входе: GPU часть времени ждёт.
4. **Общий префикс.** 393 из 427 токенов одинаковы для всех запросов, но считаются каждый раз заново.
5. **lm_head** — ~1.4 мс, читает веса всего словаря ради двух токенов (`safe`, `unsafe`).

Linear-слои работают нормально, разница `generate` и голого `forward` в пределах шума.
