# Короткая диагностика ProtectAI и AccuKnox на T4

25 ноября 2026: четыре отдельных процесса завершились успешно, по два коротких
нейтральных текста в batch 2 на процесс. Проверены нативная загрузка/вызов и
существующий адаптер каждой модели. Это **не полный smoke**, не benchmark,
не оценка качества и не подтверждение исправления ошибки RTX 5090.

| Модель | Нативный путь | Адаптер | Precision | Максимальная разница scores |
|---|---|---|---|---|
| ProtectAI | passed | passed | FP32 | 2.90e-8 |
| AccuKnox | passed | passed | BF16 backbone, FP32 readout | 3.45e-8 |

Вердикты нативного пути и адаптера на этих двух текстах совпали. Для ProtectAI
нативные logits преобразованы в probabilities офлайн с FP64 softmax; поэтому
указанная разница не является прямым сравнением logits. Для AccuKnox сравниваются
нативные probabilities с нормализованными scores адаптера.

## Условия

- Kaggle, только GPU 0: Tesla T4, драйвер 580.178.04.
- Python 3.13.16, Torch 2.11.0+cu130, CUDA 13.0, cuDNN 91900.
- Отдельные venv из неизменённых `team_rtx` и `team_d3` lock-файлов;
  установленный inventory проверен перед вызовами. Основной runtime не изменён.
- Transformers 5.20.1 для ProtectAI, 5.17.0 для AccuKnox.
- `CUDA_LAUNCH_BLOCKING=1`, стандартная асинхронная загрузка HF,
  два CPU-потока, seed 42, TF32 выключен.
- Авторский D3: SDPA, BF16 backbone и FP32 readout на CUDA. Нативная аппаратная
  поддержка BF16 у T4 отсутствует, но эти вызовы выполнились; dtype не заменялся.
- Аппаратная проверка вынесена в отдельную диагностическую обёртку T4.
  Production-профили и исходники адаптеров не менялись.

Успех при `CUDA_LAUNCH_BLOCKING=1` не подтверждает обычное асинхронное исполнение.
Матрица длин/батчей, A-B-A, пограничные входы и оптимизации здесь не проверялись.
Поле `monitor_method` в паспорте унаследовано от функции описания runtime:
sampler не запускался, показатели памяти и скорости не измерялись.
