# FP8 на RTX 5090 (gliner + HiveTraceGuard) — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** код, который на поде RTX 5090 в среде У1 v4 + torchao снимает скорость (протокол У1) и качество (tails_v2) для `bf16c` и `fp8` у gliner и HiveTraceGuard, и офлайн-анализ результатов.

**Architecture:** вливаем У1 v4 в `research/quantization`; квантование живёт во внешнем адаптере `u2_quant/adapter.py` — тонкой обёртке над `NativeAdapter` У1 (подготовка входа и разбор вердикта — штатные), поверх которой применяется torchao FP8 и `torch.compile`. Конфиги кандидатов генерируются из `configs/v4/*.json` У1. Качество считает режим `quality` У1, статистику — наш офлайн `u2_quant/analyze.py`.

**Tech Stack:** Python 3.13, torch 2.11.0+cu130, transformers 5.20.1, gliner2 2.1.0, torchao (одна добавленная версия), unittest (как в У1), pandas.

**Spec:** `docs/specs/2026-11-15-quant-5090-spec.md`

## Global Constraints

- Все изменения — в `research/quantization`; новых веток нет; `git push` только по явной команде пользователя.
- Профиль `team-rtx-quant` = `env/team_rtx.lock.json` + ровно один пакет `torchao`; остальные записи lock побайтно совпадают.
- Существующие функции У1 не меняют поведение; изменения в коде У1 — только `environment.py` и `tools/benchmark.py` (новый профиль).
- Пути на поде: только `/workspace/u2-*`; `HF_HOME=/workspace/u2-hf`; сетевой том коллег не используется.
- seed 17; comparison `quantization`; `quality_batch_sizes: [1]`.
- Сетки скорости = пресеты У1: gliner `{"B1":[1,256]}`; hive `{"B1":[1,64],"B2":[1,32],"B3":[1,16],"B4":[1,8]}`.
- tails_v2: `AutotuneGuardrails/tails`, тег `v2`, 7 121 строка; `harm → unsafe`, `safe → safe`.
- Локальные тесты — CPU, офлайн (`HF_HUB_OFFLINE=1`), без CUDA; всё, что требует GPU, — в preflight на поде.

## Review Focus

1. **torchao не импортируется / FP8 не поддержан на sm_120 с torch 2.11** → должно падать в preflight на поде до любых замеров, а не посреди baseline. Тест: `test_pod_run_dry_run_order` (preflight — первый шаг после setup).
2. **`NativeAdapter.check_device` отвергает FP8-параметры** («Physical parameter precision differs») → адаптер явно вызывает проверку после квантования и пишет понятную ошибку; на поде ловит preflight. Тест: `test_check_device_called_after_quantization`.
3. **Строки длиннее лимита** (gliner 512 токенов) исключаются У1 → coverage < 1; анализ должен считать только общие успешные ID и печатать coverage. Тест: `test_analyze_uses_common_ids_and_reports_coverage`.
4. **HiveTraceGuard сгенерировал не `safe`/`unsafe`** → строка получает статус ошибки в У1; анализ считает её как failure, а не как смену. Тест: `test_analyze_counts_failures_separately`.
5. **Перекомпиляция во время замера** (dynamic shapes) → после прогрева число компиляций фиксируется в metadata; адаптер падает, если прогрев не вызвал ни одной компиляции. Тест: `test_prepare_raises_without_compile`.
